# AI 小说自动写作工作台产品说明

版本：v1.0  
更新日期：2026-08-11

## 1. 产品定位

本项目面向长篇小说作者，当前交付形态是“单项目自动写作驾驶舱”。

系统负责把项目设定、章节规划、人物关系、冲突、伏笔、上下文检索、正文生成、章后分析和健康检查串成一条可观察的自动化流水线。它不是通用聊天应用，也不再提供一组彼此割裂的手工维护页面。

## 2. 当前用户入口

应用只保留三个路由入口：

1. 项目列表：创建、搜索、进入或删除小说项目。
2. 自动写作驾驶舱：启动、暂停、恢复和终止自动写作任务。
3. 项目设置：维护项目基础信息、AI Provider、提示词和导出。

故事圣经、人物、关系、冲突、伏笔、大纲和健康指标是驾驶舱的上下文与观察维度，不再作为独立页面暴露。

## 3. 核心工作流

```text
创建项目并完成基础配置
  ↓
建立章节范围和写作目标
  ↓
显式启动自动写作任务
  ↓
逐章构建项目上下文
  ↓
生成并校验大纲与正文
  ↓
构建、评估和修复变更集
  ↓
按自动决策策略写回或隔离
  ↓
生成章后记忆与叙事事件
  ↓
更新人物、关系、冲突、伏笔和健康指标
```

## 4. 驾驶舱信息结构

驾驶舱由四部分组成：

1. 运行控制：写作范围、策略、目标章节数和每章目标字数。
2. 章节流水线：展示每章及其处理步骤的实时状态。
3. 叙事事件流：展示自动分析产生的变更，支持采纳或隔离。
4. 叙事状态看板：人物、关系、冲突、伏笔、剧情方向和健康风险。

章节正文、大纲和场景通过章节详情抽屉查看和编辑。

## 5. 自动化授权边界

用户启动自动写作任务时，只授权系统处理所选项目、章节范围和策略。

系统必须：

- 通过结构化变更集记录生成内容及其去向。
- 在写回前执行一致性检查和自动风险判断。
- 隔离无法安全处理的高风险或异常结果。
- 保留运行、步骤、变更、事件和版本记录。
- 允许用户暂停、终止任务，并在事件流中采纳或拒绝待处理内容。

系统不得跨项目读取或写入数据，不得把失败或隔离内容伪装成已完成。

## 6. 核心领域

- 项目与故事圣经
- 分卷、幕、章节、场景与节拍
- 人物、人物弧光与关系
- 冲突、冲突时间线与伏笔
- AI 上下文快照、知识检索与写作人格
- 写作任务、自动运行与步骤
- 章节变更集、章后建议与作者事件
- 版本、健康报告与 AI 用量

这些领域仍由后端和共享契约维护，即使没有独立前端页面。

## 7. 当前非目标

- 恢复旧式多页面手工工作台。
- 在前端保留未挂载的 CRUD store 或 API 包装层。
- 多用户协作、出版发行和复杂权限系统。
- 直接仿写参考作品或输出大段受版权保护的原文。
- 未经明确任务授权的后台持续写作。

## 8. 完成标准

一次自动写作运行只有在以下条件满足时才算完成：

1. 所选章节均有确定的完成、跳过、隔离或失败状态。
2. 正文写回经过变更集与自动决策流程。
3. 章后记忆和健康指标已更新或明确记录失败。
4. 驾驶舱能展示运行结果和异常原因。
5. 仓库通过 `pnpm check`。
