# UI Implementation Rules

版本：v1.0  
更新日期：2026-08-11

## 1. 当前页面边界

前端只维护：

1. 项目列表
2. 自动写作驾驶舱
3. 项目设置

不得重新引入旧式故事圣经、人物、大纲、关系、冲突、伏笔或写作独立页面，除非产品边界经过明确确认。

## 2. 分层

- `views` 只处理路由、布局和功能组合。
- `features/automation-cockpit` 负责驾驶舱组件、组合式逻辑和远程状态。
- `features/settings` 负责项目设置。
- `stores` 只保留当前入口使用的跨组件状态。
- `api` 统一处理 HTTP；业务组件不直接拼接 fetch。

删除或新增前端模块时，应从 `main.ts` 和路由入口验证静态可达性。

## 3. 设计系统

优先使用 `packages/ui` 的布局、按钮、输入、面板、抽屉、弹窗、确认、Toast 和状态组件。

- 图标使用 Lucide。
- icon-only 按钮必须有 `aria-label` 和 tooltip。
- 业务样式使用 token，不新增裸色值。
- 不使用原生 `alert`、`confirm` 或 `prompt`。
- 不使用 emoji 作为功能图标。

## 4. 驾驶舱布局

桌面端主区域采用双栏：

- 左侧：任务控制、章节流水线、事件流。
- 右侧：人物、关系、冲突、伏笔、剧情方向和健康风险。
- 章节正文、大纲和场景使用详情抽屉。

主控制区必须是视觉中心。移动端改为单栏和抽屉，不压缩双栏。

## 5. 自动化操作

- 启动前显示范围、策略、章节数和目标字数。
- 运行中提供暂停、恢复和终止。
- 步骤状态和失败原因必须可见。
- 自动修复必须说明目标章节和处理结果。
- 采纳、拒绝、删除和正文覆盖必须说明影响并提供必要确认。

## 6. 状态与表单

- 页面和关键面板覆盖 loading、empty、error。
- 保存操作覆盖 saving、saved、failed。
- 表单字段有可见 label。
- loading 时禁用重复提交。
- 后端错误显示在页面或 Toast 中。
- 危险操作使用 `NConfirmDialog`。

## 7. 响应式验收

前端 UI 改动至少检查：

- 1440px
- 1024px
- 390px

重点检查文本溢出、按钮挤压、抽屉关闭、焦点状态和横向滚动。

## 8. 验证

```bash
rg -n "alert\\(|confirm\\(|prompt\\(" apps/web/src
rg -n "#[0-9a-fA-F]{3,8}" apps/web/src
pnpm check
```
