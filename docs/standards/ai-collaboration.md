# AI Collaboration Rules

版本：v1.0  
更新日期：2026-08-11

## 1. 授权模型

AI 只能在用户明确启动的自动写作任务范围内工作。授权范围由项目、章节范围、运行策略和目标字数共同确定。

普通页面操作、聊天结果或失败重试不自动扩大授权范围。

## 2. 写回边界

自动生成内容必须经过：

1. 上下文快照
2. 内容生成
3. 一致性检查
4. 结构化变更集
5. 自动风险决策
6. 写回、修复、跳过或隔离

高风险、无法定位或校验失败的内容不得直接写入正文和叙事台账。

## 3. 可追踪性

系统应保留：

- 自动运行和章节任务
- 每一步的状态、耗时和错误
- AI 上下文快照
- 章节变更集和条目
- 自动决策及风险级别
- 章后建议、作者事件和版本

驾驶舱必须能把完成、失败、跳过和隔离区分开。

## 4. 作者控制

作者必须能够：

- 在启动前选择任务范围和策略。
- 暂停、恢复或终止运行。
- 查看章节正文、大纲、场景和步骤状态。
- 采纳或拒绝待处理的叙事事件。
- 看到自动修复处理的目标和结果。

## 5. 项目与内容安全

- 所有详情、更新、删除和自动处理必须校验 `projectId` 归属。
- 知识库只用于摘要、结构和技巧检索，不输出连续仿写内容。
- 日志和错误信息不得泄露 API Key。
- 导出和删除必须由用户显式触发。

## 6. 开发代理规则

开发代理必须：

1. 阅读 `AGENTS.md` 及其当前必读文档。
2. 先处理失败的检查，再添加功能。
3. 保持数据库 schema 与迁移一致。
4. 不使用 `any` 掩盖领域契约问题。
5. 不绕过设计系统或项目归属校验。
6. 不恢复已移除的旧多页面前端，除非用户明确改变产品边界。
7. 在交付前运行 `pnpm check` 并报告结果。
