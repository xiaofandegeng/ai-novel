# AI 小说自动写作驾驶舱 UI 规格

版本：v1.0  
更新日期：2026-08-11

## 1. 设计目标

界面服务于长时间运行、观察和干预自动写作任务。视觉应安静、专业、信息清晰，重点突出任务状态、异常风险和作者可执行的操作。

## 2. 页面结构

### 项目列表

- 展示项目名称、题材、状态、目标字数和更新时间。
- 支持搜索、创建、进入和二次确认删除。
- 必须提供 loading、empty 和 error 反馈。

### 自动写作驾驶舱

桌面端采用“主控制区 + 叙事状态区”双栏布局：

```text
顶部：项目概览与刷新
左侧：运行控制 / 章节流水线 / 叙事事件流
右侧：人物 / 关系 / 冲突 / 伏笔 / 剧情方向 / 健康风险
浮层：章节正文、大纲和场景详情抽屉
```

主控制区是视觉中心。健康风险和异常状态必须比普通统计更醒目，但不使用装饰性高饱和色。

### 项目设置

- 项目基础信息
- AI Provider 和模型配置
- 提示词与故事结构模板
- 项目导出和删除

危险操作必须使用统一确认组件。

## 3. 设计系统

业务页面优先使用 `packages/ui`：

- `NAppLayout`
- `NButton` / `NIconButton`
- `NInput` / `NTextArea` / `NSelect`
- `NPanel` / `NDrawer` / `NModal`
- `NConfirmDialog` / `NToast`
- `NTag`
- `NEmptyState` / `NLoadingState` / `NErrorState`

业务样式使用 `packages/ui/src/tokens.ts` 和 UnoCSS token，不在页面中新增裸色值。图标使用 Lucide，不使用 emoji 功能图标。

## 4. 状态表达

运行、章节和步骤状态必须同时使用文字、图标或形状，不得只依赖颜色。

必须覆盖：

- idle / pending
- running
- paused
- completed
- failed
- skipped
- isolated
- abandoned

加载、空数据、错误、禁用和焦点状态必须可见。

## 5. 自动化交互

- 启动任务前明确展示范围、策略、目标章节数和目标字数。
- 运行中提供暂停和终止入口。
- 章节流水线展示当前步骤和失败原因。
- 叙事事件展示来源、目标、状态和可执行动作。
- 采纳、拒绝、覆盖正文和删除操作必须说明影响范围。
- 一键风险修复必须显示将处理的章节；无法定位的风险不得提供假按钮。

## 6. 章节详情抽屉

抽屉支持正文、大纲和场景三个视图：

- 正文编辑必须显示保存中、已保存和失败状态。
- 大纲与场景信息保持只读或显式保存，不进行隐式覆盖。
- 桌面端宽度应足以阅读长文本；移动端使用全屏。
- 支持关闭按钮和 Esc，焦点不能遗失到遮罩后方。

## 7. 响应式

验收宽度：

- 1440px：双栏驾驶舱完整展示。
- 1024px：右侧状态区允许收窄或切换为分区。
- 390px：单栏布局，状态看板和章节详情使用抽屉或分段切换。

不得出现横向滚动、不可关闭抽屉、按钮挤压或正文无法编辑。

## 8. 可访问性

- 所有交互元素支持键盘访问。
- icon-only 按钮有 `aria-label` 和 tooltip。
- 输入字段有可见 label。
- 普通文本对比度不低于 4.5:1。
- 动效遵循 `prefers-reduced-motion`。
- 错误信息说明发生了什么、是否影响已保存内容以及下一步操作。

## 9. UI 验收

前端改动完成后：

1. 检查项目列表、驾驶舱和项目设置。
2. 检查 1440px、1024px 和 390px。
3. 检查 loading、empty、error 和危险操作确认。
4. 检查自动任务的启动、暂停、恢复、终止和风险修复反馈。
5. 运行 `pnpm check`。
